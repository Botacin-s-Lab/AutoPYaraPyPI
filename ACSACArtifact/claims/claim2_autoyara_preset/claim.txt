CLAIM 2 - The AutoYara (VBGMM) preset generates a valid YARA rule
================================================================================

CLAIM
    Given a directory of samples, AutoPYara's `preset="AutoYara"` pipeline runs
    end to end -- byte n-gram extraction, Bloom-filter isolation, spectral
    co-clustering, and rule synthesis -- and emits a syntactically valid YARA
    rule that compiles and can scan files.

WHY THIS CLAIM EXISTS
    This is the baseline of the two pipelines the tool offers: the standard
    AutoYara approach, using a Variational Bayes Gaussian Mixture Model for
    clustering. It exercises every stage of the system except the augmented
    clustering path, which Claim 3 covers.

WHAT IS VERIFIED
    1. generate() completes without error on the synthetic proxy corpus.
    2. The returned dictionary contains the documented keys, including
       rule_string, k_clusters, strings, file_count and TP.
    3. rule_string is non-empty and is syntactically well-formed YARA:
       it declares a rule, has a strings: section with at least one hex
       string, and has a condition: section.
    4. The rule is accepted by the yara-python compiler -- i.e. it is real,
       usable YARA, not merely plausible-looking text.
    5. The compiled rule can be executed against a file without error.
    6. The rule name honours the caller's `rule_name` argument.

HOW TO RUN
    ./run.sh

    Prerequisites: ../../install.sh has been run, and Claim 1 passes.
    Runtime: roughly 1-3 minutes.

EXPECTED RESULT
    A check-by-check report ending in "CLAIM 2: PASS", exiting 0. The generated
    rule is printed (truncated) so it can be inspected.
    See expected/expected_output.txt.

WHAT IS *NOT* CLAIMED
    That the emitted rule is a useful detection signature. The input is a
    synthetic corpus we constructed (see ../../use.txt), so the rule matches
    fabricated structure, not any real malware family. The claim is about the
    pipeline functioning, not about detection quality.

THESE NUMBERS ARE NOT A BENCHMARK
    Claim 2 and Claim 3 exercise the two pipelines the tool offers. The figures
    they print - TP rate, cluster count, gram size, string count - must NOT be
    read as a comparison between the two approaches.

    On the synthetic proxy corpus both pipelines saturate: in repeated runs
    both reached a 6/6 TP rate every time. A benchmark on which both methods
    score perfectly cannot distinguish them, and synthetic data cannot support
    a claim about either method's behaviour on real malware regardless.

    Any comparative claim rests on the paper's evaluation against its real
    malware corpus, not on this artifact.

RELATION TO THE PAPER
    Demonstrates the baseline pipeline the paper's AutoYara-preset results were
    produced with. It does not reproduce those numerical results, which require
    the non-redistributable malware corpus described in ../../use.txt.
