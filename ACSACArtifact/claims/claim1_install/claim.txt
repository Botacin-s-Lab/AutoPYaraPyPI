CLAIM 1 - AutoPYara installs and its JVM backend initializes correctly
================================================================================

CLAIM
    AutoPYara can be installed from the provided source, its Java backend
    starts successfully under JPype, and the pre-trained Bloom filter data it
    depends on is present and complete.

WHY THIS CLAIM EXISTS
    AutoPYara is a two-language system: a Python frontend driving a Java
    backend over JPype, with ~600 MB of Bloom filter data fetched separately at
    install time. Any of those three pieces can be independently broken. This
    claim verifies all three are in place before the functional claims are
    attempted.

    This is the recommended "kick the tires" check. It runs in under a minute
    and requires no rule generation.

WHAT IS VERIFIED
    1. The `autopyara` package imports and reports its version.
    2. Constructing AutoPYara() starts a JVM and loads AutoYara.jar. This is
       where a missing or too-old JRE would surface.
    3. All four Bloom filter sets are present on disk
       (ember/benign, ember/malicious, autopyara/benign, autopyara/malicious).
    4. The synthetic proxy corpus generator produces a well-formed corpus with
       the expected family structure.

HOW TO RUN
    ./run.sh

    Prerequisite: ../../install.sh has been run successfully.

EXPECTED RESULT
    The script prints a check-by-check report and ends with
    "CLAIM 1: PASS", exiting 0. See expected/expected_output.txt.

RELATION TO THE PAPER
    Supporting infrastructure. This claim demonstrates the artifact is
    functional; it does not correspond to a numerical result in the paper.
