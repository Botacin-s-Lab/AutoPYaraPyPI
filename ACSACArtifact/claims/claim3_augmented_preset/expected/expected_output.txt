READING THE THRESHOLD SEARCH OUTPUT
    "Optimizing Threshold for Target K=2" ... "Final Opt: Threshold=50.00, K=6"
    is the ssdeep/DBSCAN stage searching for a similarity threshold. On the
    synthetic proxy corpus the fuzzy hashes carry little usable similarity
    signal -- pseudo-random data does not fuzzy-hash into tight families -- so
    the search often settles with each sample in its own cluster.

    That is a property of the synthetic input, not a defect, and it does not
    affect this claim: what is being verified is that the augmented path runs
    and derives a k, not that it recovers the corpus's ground-truth families.
    Cluster-recovery quality is a question for real malware, which this
    artifact cannot ship.
